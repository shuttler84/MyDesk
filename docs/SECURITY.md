# 安全说明

MyDesk 的安全目标是：即使设备或数据库文件落入他人之手，保险箱内容依然保密；同时保证应用本身不成为执行不可信内容的通道。

## 1. 私密保险箱

- **主密码**：独立于系统，≥8 位；不落盘、不写日志、不进入普通备份明文。
- **密钥派生**：Argon2id（hash-wasm 实现，memory-hard），参数 64 MiB / t=3 / p=4 / 32B 输出，随机 16B salt。参数作为加密元数据完整保存，未来可平滑升级。
- **数据加密**：AES-256-GCM（Node 内置 crypto，认证加密），随机 12B nonce，AAD 绑定容器格式版本。使用成熟库，未自行实现任何算法。
- **内存纪律**：派生密钥仅存在于主进程内存；锁定（手动/闲置/退出）时 `fill(0)` 主动擦除。
- **无恢复后门**：主密码丢失 ⇒ 数据不可解密。软件重装、换机均可，但保险箱必须依赖主密码。
- **主密码更改** = 密钥轮换：旧密码验证 → 新 salt 重新派生 → 全量重加密 → 事务持久化；失败不影响旧数据。

## 2. 应用边界

- `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`。
- Preload 只暴露通道白名单内的 `invoke`；主进程对每个 IPC 输入做 zod 校验（类型/长度/枚举/URL 协议）。
- 阻止渲染进程任意导航与 `window.open`；外部链接一律转交系统浏览器且仅限 http/https。
- CSP 限制 `script-src 'self'`，图片允许 https/data（用于网页图标与预览图）。

## 3. 不可信内容处理

- 网页元数据抓取（收藏模块）：
  - 仅 http/https；8 秒超时；响应体上限 2MB；
  - HTML 仅做正则/字符串解析，**绝不执行、绝不注入页面**；
  - 抓取结果在 UI 中以纯文本渲染（React 转义），图片以 `<img>` 加载（不执行脚本）。
- 全局搜索永远不包含保险箱；锁定状态下保险箱相关 IPC 一律拒绝。
- 普通导出（JSON/CSV/MD）永不包含保险箱内容；日志不输出密钥/密码/明文。

## 4. 数据完整性

- 数据库 WAL 模式 + 外键约束 + 事务。
- 备份归档含逐文件 SHA-256 清单；导入前强制校验 + `integrity_check` + 自动安全快照，失败自动回滚。
- 迁移事务化、可回滚；遇到更高 Schema 版本拒绝启动写入。

## 5. 已知边界（如实说明）

- 保险箱解锁期间，明文条目在主进程与渲染进程内存中可见（与主流密码管理器一致）；锁定即清除。
- 剪贴板清理为"尽力而为"：若用户在定时清理前复制了其他内容，则不覆盖用户内容。
- 本软件不能防御已感染恶意软件的操作系统（键盘记录器等超出本地应用防护范围）。
